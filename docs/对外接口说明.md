# 文物视频一键训练 —— 对外接口说明（v1）

上传一个或多个文物视频，平台自动完成 **切帧 → 清洗 → 自动标注 → 质量闸门 → 训练 → 评估 → TFLite 导出与校验 → 打包**，
最终交付 `model.pt`、已校验的 `model.tflite`、`labels.txt`、`model_card.json`。

- 接口根路径：`http://<服务器>:<端口>/api/v1`（端口以部署时启动脚本的输出为准，默认 8000）
- 交互式文档：`/api/v1/docs`
- 调用示例：仓库中的 `examples/pipeline_client.py`（上传 + 建任务 + 轮询 + 下载）、`examples/webhook_receiver.py`（回调验签）

---

## 1. 鉴权

在控制台“一键训练 → API Key 管理”（管理员）中创建 API Key。**完整的 Key 和 webhook 签名密钥只在创建时显示一次。**

```
X-API-Key: myo_sk_xxxxxxxx_xxxxxxxxxxxxxxxxxxxxxxxx
```

（也接受 `Authorization: Bearer myo_sk_...`）

| 权限范围 | 允许 |
|---|---|
| `pipeline:write` | 上传视频、创建 / 取消 / 续跑任务 |
| `pipeline:read` | 查询任务、事件 |
| `artifacts:read` | 下载交付物 |

每个 Key 只能看到自己创建的任务；访问别人的任务返回 404。

---

## 2. 典型流程

```
1.（可选，大文件）分片上传每个视频 → upload_id
2. POST /pipeline/jobs 创建任务 → job_id（HTTP 202）
3. 轮询 GET /pipeline/jobs/{job_id}（或等 webhook）
     succeeded    → GET /pipeline/jobs/{job_id}/artifacts 下载交付物
     needs_review → 质量闸门发现异常，等待人工在控制台处理，处理后自动继续
     failed       → 看 error.code / error.message；修复后可 POST /resume 续跑
```

小视频（单个 < 几百 MB）可以直接用 multipart 把视频和任务一起提交；大视频建议分片上传（支持断点续传）。

## 3. 创建任务

### 3.1 multipart 方式（视频随请求上传）

```bash
curl -X POST http://HOST:PORT/api/v1/pipeline/jobs \
  -H "X-API-Key: $KEY" -H "Idempotency-Key: 7f3c...（建议每个业务请求生成一个 UUID）" \
  -F 'spec={"name":"文物批次-2026-10","classes":[{"name":"JadeCup","display_name":"玉杯"},{"name":"AncientBowl","display_name":"古碗"}],
           "videos":[{"class":"JadeCup","file":"cup_01.mp4"},{"class":"JadeCup","file":"cup_02.mp4"},{"class":"AncientBowl","file":"bowl_01.mp4"}]}' \
  -F "videos=@cup_01.mp4" -F "videos=@cup_02.mp4" -F "videos=@bowl_01.mp4"
```

`videos[].file` 填对应上传文件的文件名；上传文件数与 `videos` 数量相同时也可以省略，按顺序对应。

**一个视频里拍了几件不同文物**时，用 `classes` 代替 `class`：

```json
"videos": [{"classes": ["JadeCup", "AncientCloth"], "file": "desk_01.mp4"}]
```

**参考图（强烈建议提供）**：每个类别可附 1~3 张该文物的清晰照片（目录照或裁剪图），用 `references` 文件字段上传，
在 `classes[].references[].file` 里按文件名引用；照片里文物只占一部分时可给像素框 `box`：

```bash
  -F 'spec={..., "classes":[{"name":"JadeCup","display_name":"玉杯","references":[{"file":"cup_ref.jpg","box":[120,80,360,300]}]}, ...]}' \
  -F "references=@cup_ref.jpg"
```

没有提供参考图的类别，系统会从视频里自动挑选（见第 5 节 `references` 阶段）。

### 3.2 JSON 方式（引用分片上传的视频）

```json
POST /api/v1/pipeline/jobs
{
  "name": "文物批次-2026-10",
  "external_ref": "crm-123",
  "classes": [{"name": "JadeCup", "display_name": "玉杯", "prompt": "玉杯（古代玉质饮器）",
               "references": [{"data_base64": "data:image/jpeg;base64,/9j/4AAQ…"}]}],
  "videos": [{"key": "v1", "upload_id": "…", "class": "JadeCup"}],
  "review_mode": "on_anomaly",
  "callback_url": "https://your-system/webhooks/myolo"
}
```

### 3.3 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | 是 | 任务名称（≤128 字，不能含 `/ \ : * ? " < > \|`） |
| `external_ref` | 否 | 调用方自己的业务单号，可按它查询 |
| `classes[].name` | 是 | 类别英文名，`^[A-Za-z0-9][A-Za-z0-9_-]{0,63}$`；**顺序即 class_id**，会写入 `labels.txt`，创建后不可修改 |
| `classes[].display_name` | 否 | 中文展示名，如“玉杯” |
| `classes[].prompt` | 否 | 给视觉模型的描述，如“玉杯（古代玉质饮器）”，能提高定位准确率 |
| `classes[].aliases` | 否 | 视觉模型可能返回的其他叫法 |
| `classes[].references` | 否 | 参考图，最多 3 张：`{"file": "…"}`（multipart）或 `{"data_base64": "…"}`（JSON，≤5 MB），可选 `box: [x1,y1,x2,y2]` |
| `videos[].class` / `classes` | 二选一 | **该视频画面里出现的文物类别**：只有一类用 `class`，几类用 `classes`（列表）；每个类别至少出现在一个视频里。标注时只问视频声明的类别 |
| `videos[].key` | 否 | 视频标识，不填自动为 v1、v2…… |
| `videos[].upload_id` / `file` | 二选一 | JSON 方式用 `upload_id`；multipart 方式用 `file` |
| `videos[].expected_instances` | 否 | 每个声明的类别在同一画面里最多几件，默认 1 |
| `videos[].skip_start` / `skip_end` | 否 | 跳过片头/片尾秒数 |
| `review_mode` | 否 | `on_anomaly`（默认）/ `auto` / `full`，见第 5 节 |
| `callback_url` | 否 | webhook 地址，见第 7 节 |
| `callback_events` | 否 | 订阅的事件，默认 `["job.needs_review","job.succeeded","job.failed","job.cancelled"]`，可加 `job.started` |
| `config` | 否 | 各阶段参数，不填用默认值，见下表 |

常用 `config` 项（完整定义见 `/api/v1/docs` 或 `app/services/pipeline/spec.py`）：

| 配置 | 默认 | 说明 |
|---|---|---|
| `extract.interval_seconds` | 0.5 | 抽帧间隔 |
| `clean.max_frames_per_video` | 200 | 每个视频最多保留的帧数（决定训练数据量与复核工作量） |
| `annotate.provider` / `model` | 系统配置 | `openrouter` / `openai_compatible` / `mock`；推荐模型 `qwen/qwen3-vl-235b-a22b-instruct` |
| `annotate.min_long_edge` / `max_long_edge` | 1280 / 1280 | 发给视觉模型前把帧放大/缩小到这个长边（小分辨率画面放大后小件文物才认得出） |
| `annotate.references` | auto | `auto`：用调用方给的参考图，没给的类别自动挑；`provided`：只用调用方给的；`off`：不用 |
| `annotate.references_per_class` | 1 | 每个类别随请求发送的参考图张数 |
| `annotate.drop_risk_above` | 0.6 | 未人工复核时，风险分高于该值的帧不进训练集 |
| `annotate.budget_usd` | 系统配置 | 视觉模型费用上限，达到后暂停 |
| `gates.thresholds.<指标>.warn/pause` | 见第 5 节 | 覆盖质量闸门阈值 |
| `dataset.ratios` | [0.7,0.15,0.15] | train/val/test 比例 |
| `train.model` | yolo11n | 基础模型（yolo11n / yolo11s / yolov8n …） |
| `train.epochs` / `imgsz` / `batch` / `patience` | 100 / 640 / 16 / 20 | imgsz 必须是 32 的倍数，即 TFLite 的输入尺寸 |
| `train.min_test_map50` | 0.5 | 测试集 mAP50 低于该值时发出质量警告；`fail_below_min_map=true` 时直接失败 |
| `export.max_map_drop` | 0.01 | TFLite 相对 PT 允许的 mAP50-95 下降量 |

### 3.4 响应与幂等

- 新建：HTTP **202**，响应体为任务详情，`Location` 头为任务地址；
- 带 `Idempotency-Key` 重复提交**相同内容**：HTTP **200**，返回原任务（网络超时后重试不会重复建任务）；
- 同一个 `Idempotency-Key` 提交**不同内容**：HTTP 409 `idempotency_conflict`。

## 4. 分片上传

```
POST /api/v1/uploads                {"filename": "cup_01.mp4", "size": 734003200, "sha256": "…(可选)"}
  → {"upload_id": "…", "chunk_size": 8388608, "received": 0, "status": "uploading", "expires_at": "…"}

PUT  /api/v1/uploads/{upload_id}    请求体为分片原始字节
     Content-Range: bytes 0-8388607/734003200
  → {"received": 8388608, ...}
     分片必须按顺序；起点与服务端已接收字节数不一致时返回 409 offset_mismatch，
     error.details.received 为服务端已接收的字节数，从该位置继续即可（断点续传）

GET  /api/v1/uploads/{upload_id}    查询进度

POST /api/v1/uploads/{upload_id}/complete
  → 校验大小与 sha256、探测视频，{"status": "ready", "video": {"fps":…, "frame_count":…, "duration":…}}
```

上传完成的视频在创建任务时通过 `upload_id` 引用；每个 upload 只能被一个任务使用；未使用的上传 24 小时后过期。

## 5. 任务状态、阶段与质量闸门

| status | 含义 |
|---|---|
| `queued` | 排队中 |
| `running` | 执行中（`stage` 为当前阶段，`progress.overall` 为 0~1 的整体进度） |
| `needs_review` | 暂停，等待人工在控制台处理（质量闸门触发 / 全量复核 / 费用达到预算） |
| `succeeded` | 完成，可下载交付物 |
| `failed` | 失败，见 `error` |
| `cancelling` / `cancelled` | 取消中 / 已取消 |

阶段顺序：`ingest`（接收）→ `extract`（切帧）→ `clean`（清洗）→ `references`（参考图）→ `class_check`（视频类别校验）→
`annotate`（自动标注）→ `gate`（质量闸门）→ `dataset`（构建数据集）→ `train`（训练）→ `evaluate`（测试集评估）→
`export_verify`（TFLite 导出与三道校验）→ `package`（打包）。

**参考图与自动标注质量**（真实文物视频 100 帧、qwen3-vl-235b 实测，召回 = 人工框被找到的比例）：

| 设置 | 召回 | 精确 |
|---|---|---|
| 只有文字描述 | 0.34 | 0.73 |
| 放大到 1280 | 0.41 | 0.89 |
| 放大 + 自动挑选的参考图（默认） | 0.72 | 0.84 |
| 放大 + 人工框裁出的参考图 | 0.74 | 0.85 |

`references` 阶段为没有参考图的类别自动挑选：在该类别的帧上先检测一遍，按大小挑候选框，再把候选周围区域单独给模型核对
（认成别的类别的丢弃）。挑不出参考图的类别会在事件里警告——这些类别的召回大约只有一半，建议补充参考图后重新提交。
控制台的“类别”卡片里能看到每类用的参考图，挑错了一眼就能发现。

**复核模式 `review_mode`：**
- `on_anomaly`（默认）：自动标注后检查质量指标，正常则直接训练，超过“暂停”阈值才暂停等人；
- `auto`：从不暂停（只有某类别完全没有可用帧时失败）；
- `full`：总是暂停，所有帧人工处理后才训练（测试集即人工确认过的标准答案，指标最可信）。

**质量闸门指标（默认阈值，可通过 `config.gates.thresholds` 覆盖）：**

| 指标 | 范围 | 警告 | 暂停 |
|---|---|---|---|
| `class_check_agreement` 视频类别校验一致率 | 视频 | <0.8 | <0.6 |
| `zero_box_rate` 未检出比例 | 视频 | >0.10 | >0.25 |
| `multi_box_rate` 多框比例 | 视频 | >0.05 | >0.15 |
| `vlm_fail_rate` 视觉模型调用失败比例 | 视频 | >0.02 | >0.05 |
| `sam_fallback_rate` SAM 收框回退比例 | 视频 | >0.15 | >0.35 |
| `temporal_jump_rate` 框跳变比例 | 视频 | >0.05 | >0.15 |
| `tiny_or_truncated_rate` 过小/截断框比例 | 视频 | >0.4 | —（文物本来就小的素材很常见，只警告） |
| `kept_ratio_after_clean` 清洗保留比例 | 视频 | <0.5 | <0.2 |
| `usable_frames_per_class` 每类可用帧数 | 类别 | <100 | <40 |
| `videos_per_class` 每类视频数 | 类别 | <3 | — |
| `class_balance` 类别均衡度 | 整体 | <0.3 | — |

`class_check_agreement` = 抽查帧中“认出了声明类别（之一）”的帧 / “认出了任何东西”的帧；什么都没认出的帧不计入
（那是漏检，由 `zero_box_rate` 管），认出物品的帧少于 3 帧时不判定。

**数据集划分：** 每类 ≥3 个视频时测试集按整段视频留出（评估可信）；少于 3 个时按时间段划分，测试指标会偏乐观，
`model_card.json` 的 `evaluation_caveats` 中会注明。建议每类提供 3 个以上、从不同角度拍摄的视频。
一个视频含多个类别时整段只进一个划分，系统会兼顾各类别的测试集覆盖。

## 6. 查询、事件、取消、续跑、下载

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/pipeline/jobs?status=&external_ref=&limit=&before=` | 列表（只含当前 Key 的任务），`next_cursor` 用于翻页 |
| GET | `/pipeline/jobs/{id}` | 详情：阶段、视频漏斗、闸门结果、指标、费用 |
| GET | `/pipeline/jobs/{id}/events?after=<id>` | 事件时间线，增量拉取：下次带上返回的 `next_after` |
| POST | `/pipeline/jobs/{id}/cancel` | 取消（排队/暂停中立即取消，运行中会停止当前阶段，包括训练进程） |
| POST | `/pipeline/jobs/{id}/resume` | 续跑失败或已取消的任务，`{"from_stage": "train"}` 可指定从更早的阶段开始（已完成的部分会复用） |
| GET | `/pipeline/jobs/{id}/artifacts` | 交付物列表（名称、大小、sha256、下载地址） |
| GET | `/pipeline/jobs/{id}/artifacts/{name}` | 下载；支持 `Range` 断点续传，响应头 `X-Content-SHA256` |

交付物：

| 名称 | 内容 |
|---|---|
| `model.tflite` | float32 TFLite，已通过结构/数值/精度三道校验 |
| `model.pt` | PyTorch 权重（best.pt） |
| `labels.txt` | 类别名，行号即 class_id |
| `model_card.json` | 端侧接入参数：实测输入输出形状与布局、预处理方式（letterbox、RGB、/255、填充 114）、推荐阈值、指标、评估可信度说明 |
| `report.json` | 完整报告：每个视频的帧数漏斗、闸门结果、各阶段耗时、视觉模型用量 |
| `delivery.zip` | 以上全部打包 |

端侧实现细节（预处理、输出解析、NMS、坐标还原）见 `docs/文物MVP-TFLite端侧部署交接文档.md`，形状与类别以 `model_card.json` 为准。

## 7. Webhook

任务进入订阅的事件时，平台向 `callback_url` 发 POST：

```json
{
  "event_id": 1234,
  "delivery_id": "…",
  "event": "job.succeeded",
  "created_at": "2026-10-09T02:30:02Z",
  "job": {"job_id": "…", "name": "…", "external_ref": "crm-123", "status": "succeeded", "stage": "package",
          "progress": 1.0, "error": null, "links": {"self": "/api/v1/pipeline/jobs/…", "artifacts": "…"}}
}
```

请求头：`X-Myolo-Event`、`X-Myolo-Delivery`、`X-Myolo-Signature: t=<unix秒>,v1=<签名>`。

**验签**：`v1 == hex(HMAC_SHA256(webhook_secret, "<t>." + 原始请求体))`，并拒绝 `t` 与当前时间相差超过 5 分钟的请求。
参考 `examples/webhook_receiver.py`。

- 返回 2xx 视为送达；其他响应或超时按 10s、30s、2m、10m、30m、1h、3h 重试，之后放弃；
- 返回 410 表示不再需要，立即停止重试；
- **至少送达一次**：同一事件可能收到多次，请按 `event_id` 去重；
- 载荷只含摘要，详情请调 GET 接口；
- 默认不允许回调内网/本机地址，需要时请平台管理员配置 `WEBHOOK_ALLOWED_HOSTS`。

## 8. 错误

所有错误的格式：

```json
{"error": {"code": "invalid_spec", "message": "人能看懂的说明", "details": …, "request_id": "…"}}
```

响应头 `X-Request-ID` 与 `request_id` 相同，联系平台排查时请提供。

| HTTP | code | 含义 |
|---|---|---|
| 401 | `unauthorized` | 缺少或无效的 API Key |
| 403 | `forbidden_scope` | Key 没有该操作的权限 |
| 404 | `not_found` | 任务/上传不存在（或不属于当前 Key） |
| 409 | `idempotency_conflict` | 同一 Idempotency-Key 用于了不同内容 |
| 409 | `invalid_state` | 当前状态不允许该操作（如取消已结束的任务） |
| 409 | `offset_mismatch` | 分片起点不对，按 `details.received` 续传 |
| 413 | `payload_too_large` | 视频超过大小上限 |
| 422 | `invalid_spec` | 参数不合法，`details` 中给出具体字段 |
| 422 | `video_unreadable` | 视频无法解码或格式不支持 |
| 422 | `checksum_mismatch` | 分片上传的 sha256 校验失败 |
| 507 | `insufficient_storage` | 服务器磁盘空间不足 |

任务失败时 `job.error.code` 取值：

| code | 含义 | 建议 |
|---|---|---|
| `extract_failed` | 所有视频都无法读取/抽帧 | 检查视频格式与完整性 |
| `no_usable_frames` | 清洗/标注后没有可训练的帧 | 视频过暗/过曝/模糊，或文物没出现在画面中 |
| `vlm_unavailable` | 视觉模型接口不可用（鉴权失败、持续超时） | 联系平台检查配置；恢复后 `resume` |
| `gate_failed_hard` | auto 模式下某类别没有任何可用帧 | 补充该类视频，或改用 on_anomaly 人工处理 |
| `rejected_by_operator` | 被人工驳回 | 见 `error.message` 中的驳回原因 |
| `dataset_failed` | 构建数据集失败（如某类别在训练集中没有样本） | 补充视频 |
| `train_failed` / `evaluate_failed` | 训练 / 评估失败 | `resume`；仍失败请联系平台 |
| `tflite_export_failed` / `tflite_verify_failed` | TFLite 导出失败或校验未通过 | 联系平台 |
| `interrupted` | 服务多次重启都没能跑完 | `resume` |

## 9. 出问题时在控制台定位

控制台（同一地址的根路径）→“一键训练”：

1. 按名称、业务单号或 job_id 搜到任务；
2. 详情页的**阶段**列表显示卡在哪一步、失败原因（训练失败可展开日志末尾）；
3. **质量闸门**表列出超阈值的指标及所在视频，点“查看帧”只看相关的帧（可叠加显示视觉模型的粗框、SAM 框和最终框）；
