# 文物视频一键训练流水线 —— 设计方案（v2）

> **已被 v3 部分修订**，见 `文物视频一键训练流水线-设计方案-v3.md`：复核策略由“必经全量复核”改为“按异常暂停”，并新增对外 API、Docker 单端口部署与安全加固。两者冲突时以 v3 为准。

> 目标：用户上传一个或多个文物视频 → 系统自动完成 **切帧 → 数据清洗 → 自动标注（VLM 粗标 + SAM 精修）→ 人工复核（必经）→ 数据集构建 → 自动训练 → 选出最佳模型 → 导出并校验 TFLite**，最终交付可直接给端侧使用的 TFLite 交付包。
>
> v2 相对 v1 的变化：
> 1. 借鉴开源项目 [AutoLabelimage-pro-max](https://github.com/Mitsuha3333/AutoLabelimage-pro-max)（MIT）的 **"VLM 粗标 → SAM 精修 → 质量闸门 → 人工修正"** 标注范式，替换 v1 的"VLM + YOLOE 融合"作为主链路；
> 2. **人工复核由可选改为必经环节**，未复核的数据不允许进入训练；
> 3. **TFLite 导出由可选改为必经环节**，并增加基于测试集的精度校验，校验不通过则流水线不算完成。

## 1. 参考项目分析：取其精华

### 1.1 AutoLabelimage-pro-max 是什么

一个 PyQt5 桌面标注工具，面向 YOLO 目标检测，核心流程：

```
图片 ─→ Qwen3-VL 粗标 ─→ SAM 精修 ─→ 人工修正 ─→ YOLO 标注
        (0~1000 相对坐标)  (框 → mask → 紧致框)  (拖拽微调/确认)
```

VLM 通过 llama.cpp 在本地以 **OpenAI 兼容接口**运行，SAM 用 box prompt 把 VLM 的粗框收紧到目标边缘。

### 1.2 值得借鉴的设计（本方案采纳）

| # | 精华 | 参考项目中的实现 | 在本方案中的落地 |
|---|---|---|---|
| 1 | **两段式标注：VLM 负责"是什么、大概在哪"，SAM 负责"边缘精确在哪"** | `qwen_client.py` → `sam_refiner.py` | 标注阶段主链路（§5.4）。VLM 的框普遍偏松，SAM 精修正好补这个短板 |
| 2 | **SAM 精修的质量闸门 + 回退** | 粗框外扩 2% 作为 prompt；多 mask 取最高分；mask 最小外接矩形作为新框；新旧框面积比须在 0.6~1.15、中心偏移 ≤ 15% 长边、面积 ≥ 16px，否则**回退到粗框** | 原样采纳阈值作为默认值；**但回退不再静默**，而是作为风险信号计入复核优先级（§5.4.3） |
| 3 | **强约束提示词** | 类别列表自动拼成 `{class_bullets}`；要求只输出 JSON 数组、`label` 必须来自给定列表、坐标用 0~1000 相对值、"不确定就不要输出"、"没有目标返回 []"；`temperature=0` | 提示词模板可编辑，按模板内容哈希做版本号（用于缓存失效） |
| 4 | **0~1000 相对坐标约定** | 在提示词中明确规定坐标格式，并与 Qwen3-VL 的原生习惯一致 | 直接解决 v1 中"不同 VLM 坐标约定不一"的最大风险：默认选用 Qwen3-VL 系列，坐标格式由提示词固定 |
| 5 | **容错的 JSON 解析** | 先整体 `json.loads`，失败则用括号配对扫描所有 `[...]` 片段逐个尝试；逐项校验 label/bbox 合法性，非法项丢弃而不是整张失败 | 采纳，扩展为同时支持对象和数组 |
| 6 | **三层框分离保存** | `raw_qwen_boxes` / `sam_refined_boxes` / `final_boxes` 分开存，界面可分别显示/隐藏对比 | 数据库中保存自动标注的三层结果；复核界面支持图层切换（§5.5） |
| 7 | **框级溯源** | 每个框带 `source`（qwen/sam/final）与 `edited_by_user` | 采纳。由于每张图都经人工复核，可**精确统计**自动标注的通过率和平均 IoU（§5.5.4） |
| 8 | **图片级状态机 + 单张失败隔离** | 未处理 → 粗标完成 → 精修完成 → 已确认 → 已保存 / 失败（附 `last_error`），批处理中单张异常不影响整体 | 采纳并扩展复核状态（§4.2） |
| 9 | **批处理可暂停 / 继续 / 停止** | `TaskWorker` 的 pause/resume/stop | 标注阶段支持暂停（例如预算到限、云端限流时） |
| 10 | **中间结果 JSON 落盘** | `intermediate/<图片>.json` 保存每层框和错误 | 写入 `manifest.jsonl` 与数据库 |
| 11 | **类别 ID 严格按类别列表顺序** | 调整类别顺序会同步所有框的 class_id | 流水线创建后类别顺序**冻结**，一直贯穿到 TFLite 的 `labels.txt` |
| 12 | **"半自动 / 全自动"双模式** | 逐张 AI + 人工 vs 批量 AI 后统一检查 | 流水线用"全自动批量预标 + 统一复核"；标注页保留单张"AI 重标"按钮用于复核时救场 |

### 1.3 不照搬的部分（及原因）

| 参考项目的做法 | 不照搬的原因 | 本方案的替代做法 |
|---|---|---|
| PyQt5 单机桌面、单人使用 | 本系统是 Web 多人协作平台 | 复用现有在线标注 + 租约 + 乐观锁 |
| 同步 `requests` 逐张串行调用 | 几百上千帧时太慢 | `httpx` 异步 + 并发上限 + 重试 |
| 原图直接 base64 上传 | 图片 token 多、费用高、延迟大 | 长边压缩到 ~1024 再上传，坐标是相对值，压缩不影响换算 |
| 依赖官方 `segment_anything` 包 | 需额外依赖；本仓库已有 Ultralytics SAM 与模型缓存 | 复用 `endpoints/sam3.py` 的 `get_shared_sam_model`，用 Ultralytics `SAM(...)(img, bboxes=...)` |
| SAM 回退时静默使用粗框 | 丢失了"这张可能标得不好"的信号 | 回退记为风险项，提高复核优先级 |
| 无去重、无置信度、无缓存 | 视频帧高度冗余，重复调用浪费 | 清洗阶段去重；风险评分；按图片哈希缓存 VLM 结果 |

## 2. 现状盘点：本仓库可复用的能力

| 环节 | 现有实现 | 可复用程度 | 需要补的 |
|---|---|---|---|
| 切帧 | `services/frame_extraction_service.py` | 高 | 顺序读取优化、画面变化采样（可选） |
| 数据清洗 | 无 | — | 模糊/曝光/近重复/数量控制 —— **新写** |
| VLM 粗标 | 无 | — | OpenAI 兼容客户端（OpenRouter / 本地 llama.cpp）—— **新写**，借鉴参考项目 |
| SAM 精修 | `endpoints/sam3.py`（Ultralytics SAM、模型缓存、支持 box prompt） | 中 | 抽出 box → mask → 紧致框 + 质量闸门的服务函数 |
| 标注 / 复核 | `AnnotationProject` / `ImageAnnotation`，租约 + 乐观锁；`POST /projects/{id}/next` 认领下一张 | 高 | 复核状态字段、三层框、复核模式 UI、按风险排序认领 |
| 导出数据集 | `AnnotationService.export_to_dataset` | 中 | 目前只生成 `train/`；需**按视频分组划分**，且只导出已复核通过的图 |
| 训练 | `training_service.create_training_task` / `start_training` | 高 | 训练完成后**自动**登记 best 模型（现在需手动调 `endpoints/training.py` 的上传接口，且写死了 `type="yolov8"`） |
| TFLite 导出 | `endpoints/models.py::_export_pt_to_tflite`（PT → ONNX → onnx2tf，Windows 可用）、`verify-tflite`（PT/TFLite 逐元素误差对比） | 中 | 见 §5.8：函数在接口层且抛 `HTTPException`；`imgsz` 写死 640；产物不持久化（每次下载都重新转换）；只用单张图验证 |

另外两处需要注意的现有问题：
- `start_training` 中的监控线程复用了请求作用域的 `db` Session，请求结束后 Session 已关闭。编排器必须在线程内自建 `SessionLocal()`。
- `POST /annotation/projects/{id}/mark-all-completed` 可一键标记全部完成，会**绕过人工复核**，流水线创建的项目必须禁用它（§5.5.5）。

## 3. 关键设计判断

1. **"一个视频 ≈ 一件/一类文物"是最重要的先验。** 上传时为每个视频指定类别，VLM 只需在该视频的类别范围内定位，准确率更高、提示词更短。
2. **必须按视频（或时间段）分组划分训练/验证/测试集。** 相邻帧几乎相同，随机划分会让指标虚高，选出的"最佳模型"不可信。
3. **人工复核是质量底线，自动化的目标是让复核变快，而不是跳过复核。** 因此自动标注阶段的产出除了框，还有一个**风险分**，用于决定复核顺序和复核方式（网格快审 vs 逐张精审）。
4. **全量复核带来一个红利：测试集就是金标集。** v1 中担心"测试集也是自动标的，mAP 不可信"的问题随之消失；并且可以精确度量自动标注的质量，用来调阈值、选 VLM 模型。
5. **TFLite 是交付物，不是附件。** 选模型时就要考虑能否成功导出，导出后要在测试集上验证精度没有掉；校验不过 = 流水线失败。
6. **流水线必须可恢复。** 阶段产物落盘、状态入库、阶段幂等。复核环节可能持续数天，Run 在 `waiting_review` 状态下长期挂起是正常状态。

## 4. 总体流程与架构

### 4.1 流程

```
 上传视频 + 每个视频的类别
        │
        ▼
 ① 切帧 ──────────── 复用 FrameExtractionService（按视频分子目录）
        ▼
 ② 数据清洗 ──────── 模糊 / 曝光 / 近重复 / 每视频数量上限
        ▼
 ③ 视频级类别校验 ─── 每视频抽 5 帧用全类别提问，发现"视频类别选错"提前告警
        ▼
 ④ 自动标注 ──────── VLM 粗标 → SAM 精修 → 质量闸门 → 时序校验 → 风险评分
        ▼
 ⑤ 人工复核【必经】── 网格快审（低风险） + 逐张精审（高风险）
        │              全部帧处理完（通过/修改/丢弃）才能继续
        ▼
 ⑥ 构建数据集 ─────── 仅复核通过的帧；按视频分组划分 train/val/test
        ▼
 ⑦ 训练与选优 ─────── 1~N 个候选 → 统一测试集评估 → 排序
        ▼
 ⑧ TFLite 导出与校验【必经】── 导出 → 形状校验 → 数值误差 → 测试集 mAP 对比
        │                     不通过则回退到下一名候选
        ▼
 ⑨ 交付包 + 报告 ──── model.tflite + labels.txt + model_card.json + 交接文档
```

### 4.2 状态设计

**Run 状态**：`pending → running → waiting_review → running → completed`，任一阶段可进入 `failed`，用户可 `cancelled`。

**图片状态**（借鉴参考项目的 `ImageStatus`，扩展复核态）：

```
pending ─→ vlm_done ─→ refined ─→ to_review ─┬─→ accepted   （复核：原样通过）
   │                                          ├─→ modified   （复核：修改后通过）
   └──────────── failed(last_error) ─────────→┴─→ discarded  （复核：丢弃该帧）
```

`failed` 的帧（VLM 超时、解析失败等）同样进入复核，复核员可手动标注或丢弃，不会卡住流水线。

### 4.4 数据模型

**新表 `pipeline_runs`**：

```python
class PipelineRun(Base):
    __tablename__ = "pipeline_runs"

    id            = Column(UUID(as_uuid=True), primary_key=True, default=uuid.uuid4)
    name          = Column(String, nullable=False)
    status        = Column(String, default="pending", index=True)

    config        = Column(JSON, nullable=False)   # PipelineConfig 快照（含冻结的类别顺序）
    stage_states  = Column(JSON, default=dict)     # {stage: {status, started_at, ended_at, progress, error}}
    artifacts     = Column(JSON, default=dict)     # work_dir / annotation_project_id / dataset_id /
                                                   # training_task_ids / best_model_id / tflite_bundle
    metrics       = Column(JSON, default=dict)     # 漏斗、自动标注质量、候选模型指标、TFLite 校验
    llm_usage     = Column(JSON, default=dict)     # 调用次数 / token / 费用
    error         = Column(Text, nullable=True)
    created_by    = Column(Integer, ForeignKey("users.id", ondelete="SET NULL"), nullable=True)
    created_at    = Column(DateTime, default=datetime.utcnow)
    updated_at    = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
```

**`AnnotationProject` 增加**：

```python
review_required = Column(Boolean, default=False)  # 流水线项目为 True：禁用一键全部完成，导出只认复核通过
pipeline_run_id = Column(UUID(as_uuid=True), nullable=True)
```

**`ImageAnnotation` 增加**（沿用 `init_db.py` 里补协作字段的方式）：

```python
auto_annotations = Column(JSON, nullable=True)   # {"vlm": [...], "sam": [...], "meta": {...}}  三层中的前两层
review_status    = Column(String, nullable=True, index=True)  # to_review / accepted / modified / discarded
risk_score       = Column(Float,  nullable=True)  # 0~1，越高越需要仔细看
risk_reasons     = Column(JSON,   nullable=True)  # ["sam_fallback", "temporal_outlier", ...]
reviewed_by      = Column(Integer, ForeignKey("users.id", ondelete="SET NULL"), nullable=True)
reviewed_at      = Column(DateTime, nullable=True)
```

现有 `annotations` 字段即参考项目中的 `final_boxes`（第三层，人工可编辑）。每个框对象增加 `source`（`vlm` / `sam` / `manual`）与 `edited`。

**`Model` 增加**：`artifacts = Column(JSON)`，记录已持久化的 `tflite_path`、`onnx_path`、校验结果，下载接口优先返回已有文件而不是每次重新转换。

### 4.5 编排器

- 每个 Run 一个后台线程，线程内自建 `SessionLocal()`；
- 阶段顺序推进，每个阶段 `run(ctx)` 幂等（已完成的部分跳过）；
- 服务启动时把 `status=running` 的 Run 标为 `failed(interrupted)`，由用户手动"从当前阶段继续"；`waiting_review` 状态不受重启影响；
- CPU/网络阶段可多 Run 并行；训练走**全局 GPU 队列**；SAM 精修模型较小，默认与训练共用 GPU，显存不足时自动回退 CPU；
- 取消：各阶段循环内检查取消标志；训练阶段调用 `stop_training`。

## 5. 各阶段详细设计

### 5.1 上传与配置

每个视频附带类别（表格选择 / 文件名解析 `JadeCup_01.mp4` / 文件夹名解析）。

```jsonc
{
  "classes": ["JadeSeal", "JadeCup", "CalligraphyPaintings", "AncientCloth", "AncientBowl"], // 创建后冻结
  "class_prompts": { "JadeCup": "玉杯（古代玉质饮器）" },   // 给 VLM 的类别描述，可选
  "videos": [{ "file": "JadeCup_01.mp4", "classes": ["JadeCup"] }],

  "extract":  { "method": "time", "interval_seconds": 0.5, "skip_start": 1, "skip_end": 1 },
  "clean":    { "blur_drop_ratio": 0.15, "dedup_hamming": 6, "max_frames_per_video": 200 },

  "annotate": {
    "vlm_provider": "openrouter",            // openrouter / local（本地 llama.cpp，OpenAI 兼容）
    "vlm_model": "<Qwen3-VL 系列模型 ID>",
    "prompt_template_id": "default-v1",
    "sam_model": "<本仓库已有的 SAM 权重>",
    "sam_gate": { "expand_ratio": 0.02, "min_area_ratio": 0.6, "max_area_ratio": 1.15,
                  "max_center_shift_ratio": 0.15, "min_box_area": 16 },
    "quick_review_risk_below": 0.3           // 低于该风险分的帧进入网格快审
  },

  "dataset":  { "split": "by_video", "ratios": [0.7, 0.15, 0.15] },
  "train":    { "candidates": [{ "model": "yolo11n.pt", "imgsz": 640, "epochs": 100 }], "patience": 20 },
  "export":   { "tflite_precision": ["float32"],   // float32 必出；可加 float16
                "max_map_drop": 0.01 }             // TFLite 相对 PT 的 mAP50-95 允许下降量
}
```

配置页实时显示：预计帧数、预计 VLM 费用、**预计复核工作量**（例："约 820 帧，其中约 600 帧网格快审、220 帧逐张精审，预计 1.5 人时"，按历史复核速度估算）。

### 5.2 ① 切帧

调用 `FrameExtractionService.extract_from_video`，固定 `subfolder=True`。增强项（M2）：间隔较小时用顺序 `grab()/retrieve()` 替代每帧 `cap.set(POS_FRAMES)`；按画面变化量动态调整采样密度。

### 5.3 ② 数据清洗 与 ③ 视频级类别校验

**清洗**（由便宜到昂贵，原因写入 manifest，报告中可查看并捞回）：

| 步骤 | 方法 |
|---|---|
| 模糊 | 拉普拉斯方差，**视频内**按分位数剔除最低 15%（不同视频清晰度差异大，不用固定阈值） |
| 曝光 | 灰度均值 + 过曝/欠曝像素占比 |
| 近重复 | pHash 汉明距离，**仅视频内**去重，保留最清晰的一张 |
| 数量控制 | 每视频上限 + 时间均匀抽样；最少类 < 最多类 30% 时告警 |

因为要全量人工复核，清洗的激进程度直接决定复核工作量：**默认每视频上限 200 帧**，宁可少而精。

**视频级类别校验**：每个视频抽 5 帧，用**全部类别**提问 VLM。若多数帧识别出的类别与用户指定的不一致，在复核前提示"视频 X 的类别可能选错"，由用户确认后再进入标注，避免整段视频的标签全错。

### 5.4 ④ 自动标注

#### 5.4.1 主链路（借鉴参考项目）

```
帧 ──(压缩到长边1024)──→ VLM 粗标 ──→ SAM 精修 ──→ 质量闸门 ──┬─ 通过：用精修框
     提示词只含本视频类别     0~1000 相对坐标    box prompt      └─ 不通过：回退粗框 + 记风险
                                                                        │
                                          时序一致性校验（同视频相邻帧）◀─┘
                                                                        │
                                                                   风险评分 → 写入标注项目
```

**VLM 粗标**：
- 提示词沿用参考项目的强约束写法，并加入文物场景规则：

```text
你是一个严格的视觉标注器。
任务：只检测图中清晰可见的以下文物：
{class_bullets}

只返回 JSON 数组，不要任何解释。格式：[{"label":"类别名","bbox":[x1,y1,x2,y2]}]
规则：
- label 必须严格来自给定类别列表
- bbox 使用 0~1000 的相对坐标，原点在左上角，x1<x2，y1<y2
- bbox 贴合文物本体边界，不包含底座、支架、展柜、手、阴影和倒影
- 文物可见部分不足一半时不要输出
- 不确定就不要输出；没有目标时返回 []
- 不要重复输出
```

- `temperature=0`；解析用容错 JSON 扫描；非法项（label 不在列表、坐标越界或反向）逐项丢弃；
- 客户端是 OpenAI 兼容格式，`vlm_provider` 只影响 `base_url` 和鉴权：
  - `openrouter`：`https://openrouter.ai/api/v1`，Bearer 密钥来自 `.env`；
  - `local`：本地 llama.cpp 服务（参考项目的部署方式），用于**不允许图片出网**的文物，无调用费用。

**SAM 精修**：复用 `get_shared_sam_model` 的模型缓存；对每个粗框外扩 `expand_ratio` 作为 box prompt，取 mask 的最小外接矩形。

**质量闸门**（阈值采用参考项目默认值）：精修框面积 / 粗框面积 ∈ [0.6, 1.15]，中心偏移 ≤ 0.15 × 粗框长边，面积 ≥ 16px；任一不满足则回退粗框，并记 `sam_fallback`。

> 文物场景的典型回退：SAM 把底座/展台一起分进来（面积比过大），或只分出器物的一部分如器盖（面积比过小）。这些正是需要人看一眼的帧。

#### 5.4.2 时序一致性校验

同一视频内按时间排序，对框的中心、宽、高做滑动中位数，偏离超过阈值的帧记 `temporal_outlier`。拍摄时文物是连续运动的，这个校验几乎零成本且很有效。

#### 5.4.3 风险评分

| 风险项 | 含义 | 权重（初始值，M2 用复核数据回归调整） |
|---|---|---|
| `vlm_failed` | 超时 / 解析失败 | 1.0（直接最高风险） |
| `box_count_mismatch` | 视频声明 1 件文物但返回 0 个或多个框 | 0.5 |
| `sam_fallback` | 质量闸门未通过 | 0.3 |
| `temporal_outlier` | 与相邻帧不连续 | 0.3 |
| `edge_truncated` | 框贴图像边缘（文物可能被截断） | 0.15 |
| `tiny_box` | 框面积占比过小 | 0.15 |

`risk_score = min(1, Σ权重)`。`< quick_review_risk_below` 的帧进入**网格快审**，其余进入**逐张精审**。

#### 5.4.4 OpenRouter 集成细节

配置（`app/core/config.py` + `.env`，密钥不入库、不提交）：

```python
VLM_PROVIDER: str = "openrouter"             # openrouter / local
OPENROUTER_API_KEY: str = ""
OPENROUTER_BASE_URL: str = "https://openrouter.ai/api/v1"
LOCAL_VLM_BASE_URL: str = "http://127.0.0.1:8887/v1"
VLM_MODEL: str = ""
VLM_MAX_CONCURRENCY: int = 4
VLM_TIMEOUT: int = 60
VLM_BUDGET_PER_RUN: float = 0                # 美元，0 = 不限
ALLOW_CLOUD_VLM: bool = True                 # 管理员总开关，False 时强制 local
```

`vlm_client.py`：`httpx` 异步 + 信号量并发；429/5xx 指数退避；超过重试次数的帧记 `vlm_failed` 进入复核而不是让整个阶段失败；按 `sha1(图片)+模型+提示词版本` 缓存；累计 `usage` 到 `llm_usage`，超预算自动**暂停**标注阶段（借鉴参考项目的 pause/resume），用户调高预算或切换本地模型后继续。

模型选择：默认 Qwen3-VL 系列（与参考项目一致，0~1000 坐标是其原生习惯）；具体模型 ID 与价格以 OpenRouter 模型页为准，做成下拉选项。**新模型上线前**用 20 张人工标注图做校准，平均 IoU < 0.7 的不开放选择。

**数据合规**：启用云端时界面明确提示"图片将发送到第三方"；`ALLOW_CLOUD_VLM=False` 时只能用本地 llama.cpp。

### 5.5 ⑤ 人工复核（必经）

#### 5.5.1 放行规则

- 标注阶段结束，Run 进入 `waiting_review`；
- **只有当 `to_review` 数量为 0**（每一帧都是 accepted / modified / discarded）时，"完成复核，开始训练"按钮才可用，后端 `complete-review` 接口同样校验；
- 不提供"跳过未复核帧"的选项。复核员如果认为某帧不值得看，应显式"丢弃"，这样留有记录；
- 复核期间 Run 可以长期挂起，页面显示进度与各复核员贡献。

#### 5.5.2 两种复核方式

**网格快审**（低风险帧，追求速度）：
- 按视频、按时间顺序排列缩略图，每张叠加最终框；
- 连续帧放在一起，一眼就能看出哪张框"跳"了；
- 键盘：方向键移动焦点，`Space` 标记为问题帧，`Enter` 通过本页其余全部帧，点击任一张进入精审；
- 批量通过时携带每张图的 `version`，走现有乐观锁，防止覆盖他人修改。

**逐张精审**（高风险帧，追求准确）：
- 在现有标注画布上增加**图层切换**（借鉴参考项目）：VLM 粗框（虚线）/ SAM 精修框（细线）/ 最终框（实线），一键把最终框"还原为粗框"或"还原为精修框"——SAM 回退或精修过度时最常用；
- 面板显示风险原因（如"SAM 精修面积比 1.42，已回退粗框"）；
- 快捷键：`A` 通过、`D` 丢弃帧、`R` 对当前帧重新跑 VLM+SAM、`1~9` 切换选中框类别、`Del` 删除框、`←/→` 上/下一张；
- 多人协作沿用 `POST /projects/{id}/next` 的租约认领，新增 `order=risk_desc` 参数，高风险优先分配。

#### 5.5.3 复核顺序建议

先处理"视频级类别校验"告警 → 再精审高风险帧 → 最后网格快审。高风险帧中暴露的系统性问题（如某视频 SAM 总把底座包进来）可以在快审前通过"对该视频批量还原为粗框"一次性处理。

#### 5.5.4 复核带来的质量度量（全量复核的红利）

每一帧都有自动结果和人工最终结果，因此可以精确统计：
- 原样通过率、修改率、丢弃率（按视频、按类别）；
- 粗框 vs 最终框、精修框 vs 最终框的平均 IoU —— 直接量化 **SAM 精修到底有没有用**，用于调质量闸门阈值；
- 各风险项的命中率 —— 用于回归调整 §5.4.3 的权重，让风险评分越用越准；
- 不同 VLM 模型 / 提示词版本的对比 —— 为下一次 Run 选模型提供依据。

#### 5.5.5 防绕过

`review_required=True` 的项目：
- 禁用 `mark-all-completed`（返回 403 并说明原因）；
- `export_to_dataset` 只导出 `review_status ∈ {accepted, modified}` 的图；
- 标注页隐藏"全部标记完成"入口。

### 5.6 ⑥ 构建数据集

| 策略 | 适用场景 | 做法 |
|---|---|---|
| `by_video`（默认） | 每类 ≥ 3 个视频 | 以视频为单位分配，保证每类至少 1 个视频在 val、1 个在 test |
| `by_segment` | 某类只有 1~2 个视频 | 视频按时间切段，段与段之间留 2 秒缓冲带（缓冲内的帧丢弃），按段分配 |

只使用复核通过的帧；类别顺序使用冻结后的 `config.classes`；生成 `dataset.yaml`，登记 `Dataset`。

### 5.7 ⑦ 训练与选优

**训练**：每个候选调用 `create_training_task` + `start_training`，进入全局 GPU 队列；轮询状态并读取 `results.csv` 更新进度；完成后**自动**登记 `best.pt` 到 `Model` 表并回填 `output_model_id`（把 `endpoints/training.py` 中的登记逻辑抽成 service 函数，修正写死的 `type="yolov8"`）。

**imgsz 约束**：TFLite 输入尺寸固定，训练、评估、导出必须使用同一个 `imgsz`（默认 640，与现有端侧交接文档一致）。

**选优**（所有候选在同一 test 集上 `model.val(split="test")`）：

| 优先级 | 指标 |
|---|---|
| 1 | mAP50-95 |
| 2 | 最差类别 AP（防止某类完全没学会的模型因平均分高胜出） |
| 3 | 指标差距 < 1% 时，选模型更小、TFLite CPU 推理更快的 |

得到候选排名列表，交给 ⑧；若第一名 TFLite 校验失败，自动尝试第二名，并在报告中说明。

### 5.8 ⑧ TFLite 导出与校验（必经）

#### 5.8.1 先重构现有导出代码

把 `endpoints/models.py` 中的 `_export_pt_to_tflite`、`_letterbox`、`_postprocess_raw`、`_run_tflite_and_compare` 移到 `services/export_service.py`：
- 抛业务异常而非 `HTTPException`，便于在后台流水线中调用；
- `imgsz` 改为参数（取训练时的值），不再写死 640；
- 产物**持久化**到 `MODELS_DIR/<model_id>/`，并写入 `Model.artifacts`；原下载接口改为"已有则直接返回，没有才转换"；
- 保留现有 PT → ONNX（opset 12）→ onnx2tf 的路径，Windows 可用。

#### 5.8.2 三道校验关卡

| 关卡 | 检查内容 | 通过标准 |
|---|---|---|
| 1. 结构 | `tf.lite.Interpreter` 能加载；输入 `[1, imgsz, imgsz, 3]` float32；输出为 `[1, 4+nc, N]` 或其转置，且 `nc` 等于类别数 | 全部满足 |
| 2. 数值 | 从 test 集抽 20 张真实图片，同一预处理下 PT 与 TFLite 原始输出逐元素比较（复用现有 `_run_tflite_and_compare`） | float32：框坐标最大误差 < 1px，类别分数最大误差 < 1e-3 |
| 3. 精度 | 用 TFLite 在**完整 test 集**上推理（letterbox + 自写 NMS，同现有实现，不走 Ultralytics 的 LiteRT 后端），用 `ultralytics.utils.metrics.ap_per_class` 计算 mAP | mAP50-95 相对 PT 下降 ≤ `max_map_drop`（float32 默认 1%，float16 默认 2%） |

任一关卡失败：记录详细原因 → 换下一名候选重试 → 所有候选都失败则 Run 置为 `failed`，报告中给出每个候选的失败原因。

#### 5.8.3 精度选项

- **float32**：必出，与现有端侧交接文档一致；
- **float16**（可选，M2）：onnx2tf 同时会生成，体积约减半，走同样三道校验；
- **int8**（M3）：需要代表性校准数据，直接从 train 集按类别均衡抽 100~200 张，精度损失需单独评估。

#### 5.8.4 端侧推理速度参考

在服务器 CPU 上用 TFLite Interpreter 测单张平均推理耗时，写入报告作为相对参考（不代表手机真实性能）。

**交付包** `delivery/<name>_tflite.zip`：

<name>_float16.tflite        # 如启用

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| VLM 框偏松、漏检 | SAM 精修收紧 + 质量闸门；漏检（0 框）直接计入高风险；复核兜底 |
| SAM 把底座/展柜分进来，或只分出局部 | 面积比闸门回退粗框；精审一键"还原粗框"；按视频批量还原 |
| 复核工作量过大 | 清洗时限制每视频帧数；风险排序 + 网格快审；多人租约并行；工作量在配置时提前估算 |
| 数据集泄漏导致选错模型 | 强制按视频/时间段划分，报告展示划分明细 |
| TFLite 转换掉精度或结构不符 | 三道校验关卡；失败自动回退下一候选；交接文档中的形状取实测值 |
| 类别顺序在某处被改动，端侧 class_id 对不上 | 创建 Run 时冻结类别顺序，贯穿项目 → 数据集 → 模型 → `labels.txt` |
| 云端费用失控 | 图片压缩、缓存、预算上限自动暂停；可切换本地 llama.cpp |
| 文物图片外发的合规问题 | `ALLOW_CLOUD_VLM` 总开关；本地 llama.cpp 方案（参考项目已验证可行） |
| GPU 争用（训练 vs SAM） | 训练走全局队列；SAM 显存不足回退 CPU |

## 10. 需要确认的问题

1. 视频是否基本满足"一个视频只拍一件/一类文物"？多件同框会显著增加高风险帧比例。
2. 文物图片能否发送到 OpenRouter？若不能，需要准备一台能跑 Qwen3-VL 的本地 GPU 机器（参考项目推荐 8B Q4 量化版）。
3. 复核人力：有几位复核员、预期能投入多少工时？这决定每视频帧数上限的默认值。
4. 端侧目标设备与精度要求：只要 float32，还是需要 float16 / int8？是否有推理速度指标？
5. 单次 Run 的 OpenRouter 预算上限大致是多少？
